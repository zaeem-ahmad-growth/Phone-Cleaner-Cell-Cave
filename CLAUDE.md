# Rules for Claude Code in this repository

This is the public evidence site for **Phone Cleaner** by **Cell Cave**
(package `com.clearner.mobilecleaner.filemanager.cloud.savevideo.file.photo`), written for the
Google Play review team and for company management. It follows the house rules in
`CONTRIBUTING.md` - *GitHub Repository Handling Guidelines*, the same rules as every other
repository under this GitHub account. Read `CONTRIBUTING.md` before a first change.

`docs/knowledge.md` loads with this file. Answer from it whenever you can.

## What makes this repository different

- **Audience.** Every page addresses Google Play reviewers and our own management, never the
  app owner. Write in the first person plural: *we offer these features*, *we made these
  changes after the suspension*. Never "you should", never "the owner", never advice.
- **Hosting.** GitHub Pages, public, no Cloudflare Pages and no Cloudflare Access. Anyone with
  the link can read it. Do not add any gate.
- **Source of content.** The analysis lives in `zaeem-ahmad-growth/Phone-Cleaner-App`. This
  repository re-presents it. **Never edit that repository from here.**
- **Claims discipline.** Every claim on these pages is addressed to a regulator. A sentence
  that cannot be backed by a screenshot, a measured figure or a policy link does not go in.

## Layout

```
tabs/01-app-suspension/index.html   the home page: appeal, notice, audit, evidence, corrected listing
  notice/                           the suspension email screenshot
  listing/                          the suspended store art, as audited
  shots/                            app captures from the 17 Sep 2026 QA round
tabs/02-app-details/index.html      spec, versions & APK, screenshots, store graphics, QA history
  gfx/ shots/ store/                app icon, app captures, corrected store art
assets/nav.js                       the tab bar; its TABS list sets the tabs and their order
assets/bar.css assets/site.css      styling; both tab pages bring their own design on bar.css
docs/knowledge.md                   key facts and decisions - hand-written
docs/tabs/, docs/backend/, docs/code-map.md, docs/data-dictionary.md, docs/research-index.md
                                    GENERATED by GitHub after every push: never edit by hand
research/                           the source text behind the listing copy
tools/export-docs.js                the generator the "Update docs" workflow runs: never run it yourself
```

There is no `assets/data.js` or `assets/app.js` - both tabs are self-contained pages.

## Before anything

1. `git pull --rebase`.
2. Answer from `docs/knowledge.md`. Open more only when the request needs it:
   - what a tab says -> `docs/tabs/<tab>.md`
   - which file, line or function produces a section -> `docs/code-map.md`
   - how a tab works -> `docs/backend/<tab>.md` or `/backend <tab>` (large - only for code changes)
3. Wording and number edits need no scripts, no builds and no browser check.

## Writing and publishing

- One request = one edit place. Fixed wording lives in `tabs/<NN>-<name>/index.html`.
- Every page keeps `<meta name="robots" content="noindex">`, the site `<title>`
  **Phone Cleaner: Cell Cave** and the favicon link.
- Keep a tab's images inside that tab's own folder, with relative links.
- A new tab needs its line in `assets/nav.js` and one line in `docs/knowledge.md`.
- Never edit anything under `docs/` except `knowledge.md` and `README.md`; GitHub regenerates
  the rest after every push.
- No secrets: no keys, tokens, ad unit IDs, service files or store console exports.
- Commit and push without asking; push to `main` publishes the site. Never force-push.
